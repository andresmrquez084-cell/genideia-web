## Qué construir (estructura — esto NO cambia)
1. Stack, liviano a propósito:
   - Astro con renderizado en el servidor (SSR) + adaptador de Node.
   - Base de datos local en un solo archivo con `node:sqlite` (el SQLite nativo de Node) — sin
     servicio de base de datos externo ni credenciales que gestionar.
   - Tailwind para estilos.
   - Pensado para correr en tu computadora (`npm run dev`). Nada de servicios pagos para
     empezar. Dejalo preparado para empaquetar con Docker, pero NO lo despleguemos ahora.

2. Un único sistema de diseño centralizado: todos los colores, tipografías, radios y espaciados
   viven en UN solo bloque de variables CSS (`:root`, en un archivo tipo `estilos.css`). Tema
   oscuro, premium, con buen contraste. Cambiar un color ahí debe actualizar TODA la app. Todas las
   pantallas heredan de ese archivo y de un layout compartido — nunca estilos sueltos por página.

3. La portada = "el cerebro": no un menú, un mapa. En el centro, una galería flotante
   (coverflow) de tarjetas, una por módulo, con una carta focal destacada y líneas tipo "sinapsis"
   conectándolas. Arriba, un selector de "regiones" (las grandes áreas de mi negocio); al cambiar de
   región cambian las tarjetas visibles. Se navega con rueda del mouse, flechas del teclado o
   arrastrando. Fondo de estrellas/partículas sutil. Debe sentirse vivo.

4. Módulos: cada módulo es una página propia que usa el MISMO layout compartido (barra superior
   con logo + navegación, título del módulo con ícono, y KPIs arriba). Empezá creando estos y
   después sumamos los que yo pida:
   - Resumen — los números clave del negocio hoy (tarjetas de KPI) + un puntaje de "salud".
   - Clientes y crecimiento (o el equivalente de mi negocio) — el recorrido de cada cliente
     por fases. Tiene que responder tres cosas de un vistazo: en qué etapa está cada
     conversación, cuál es la próxima acción y cuándo fue el último movimiento. Arriba, un
     contador de cuántos hay en cada fase, para ver dónde se concentra la cartera. Al tocar un
     cliente, su ficha al costado con el detalle y las acciones a mano.
   - Proyectos — para cada uno: qué se propuso, qué tareas están pendientes y qué parte ya
     está en marcha. No es un portafolio: es el estado real de lo que está corriendo.
   - Procedimientos / operación — cómo se hace cada cosa que se repite, paso a paso.
   - Finanzas — ingresos, gastos, cobranzas pendientes.
   - Agenda / Tareas — lo que hay que hacer, por fecha.
   - Contenido — calendario editorial (si aplica a mi negocio).
   [ajustá esta lista a los módulos que puse arriba]

5. Movimiento: transiciones suaves al cambiar de página, animaciones de aparición al hacer
   scroll (scroll reveals), micro-interacciones al pasar el mouse, y una pantalla de carga inicial
   con mi logo. Sin librerías pesadas — CSS + lo nativo del navegador. Empaquetalo de forma reusable.

6. Acceso: login propio con usuario y contraseña (contraseñas hasheadas, sesiones guardadas en
   la base). Todo el panel detrás del login, salvo la propia pantalla de login y los archivos
   estáticos. Nunca guardar contraseñas ni claves en el código — usar variables de entorno.

7. Datos y respaldo: además de la base local, dos scripts: uno que EXPORTA todas las tablas a
   archivos JSON (`sync:out`) y otro que las IMPORTA (`sync:in`). Así puedo llevar los datos entre
   computadoras y versionarlos, sin exponer la base binaria.
