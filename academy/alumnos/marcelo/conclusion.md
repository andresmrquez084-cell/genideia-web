# Conclusión del programa — Marcelo Noceda

## Estado

**Programa finalizado.**  
Marcelo completó los 8 módulos de Genideia Academy.

No quedan clases pendientes dentro de esta etapa.

## Qué funcionó

### 1. Aprender sobre un proyecto real

Los mejores resultados aparecieron cuando cada concepto se aplicó inmediatamente sobre una necesidad real:

- plan de 90 días;
- proyecto de autos;
- investigación de precios;
- Skill “Precio Autos”;
- CRM;
- procesos de varios pasos;
- contenido audiovisual;
- proyecto final “Dato Verificado”.

La teoría sola tuvo menos valor que la secuencia:

**concepto → caso real → ejecución → corrección → reutilización**

### 2. Usar problemas de la clase anterior como parte del aprendizaje

Varias clases comenzaron cerrando algo que había quedado incompleto.

Eso fue útil cuando el problema permitía explicar una capa nueva, por ejemplo:

- Supabase, GitHub y Vercel;
- estructura de contexto;
- reglas operativas faltantes;
- convertir investigación validada en Skill.

## Qué generó fricción

### 1. Ejecutar antes de comprender la arquitectura

Cuando la ejecución técnica avanzó demasiado rápido, Marcelo podía llegar a un resultado funcional sin entender bien:

- qué herramienta hacía qué;
- dónde vivían los datos;
- qué estaba configurado;
- qué dependía de él.

**Aprendizaje para futuras clases:** antes de conectar infraestructura, explicar el mapa mínimo del sistema y después ejecutar.

### 2. Construir capas antes de estabilizar la anterior

Algunas ideas se expandieron demasiado rápido:

**proceso → Skill → CRM → conexión → automatización**

sin que todas las capas estuvieran igual de validadas.

**Nueva regla:** una capa nueva se agrega cuando la anterior produce un resultado repetible.

### 3. Demasiada amplitud en una misma clase

Cuando aparecían oportunidades nuevas, era fácil ampliar el alcance.

Para próximos alumnos conviene cerrar cada clase con un resultado principal y dejar ideas secundarias en backlog.

## Método que se conserva

### Checkpoint de entrada

Al iniciar una clase:

1. probar lo anterior;
2. confirmar qué funcionó;
3. detectar bloqueo;
4. resolver solo lo necesario;
5. avanzar cuando exista estabilidad suficiente.

### Resultado de salida

Cada clase debe dejar:

- un resultado real;
- un procedimiento guardado;
- una tarea breve;
- un criterio objetivo para saber si funcionó.

### Escalera recomendada

**NECESIDAD → INSTRUCCIÓN → CONTEXTO → INVESTIGACIÓN → PROCESO → SKILL → DELEGACIÓN → SOLUCIÓN → MEDICIÓN**

No saltar etapas solo porque técnicamente se pueda.

## Conclusión general

Marcelo confirmó que Academy funciona mejor como **acompañamiento de construcción** que como curso lineal.

La estructura de módulos sirve como mapa, pero el aprendizaje se consolida cuando el alumno:

- construye algo que necesita;
- entiende por qué funciona;
- lo prueba fuera de clase;
- vuelve con evidencia;
- y recién entonces agrega una nueva capa.
